* Spread the label, policy, and detail queries of hosts that became overdue while the Fleet server was down (e.g. during a database migration) uniformly over a configurable window after the server starts (`osquery.overdue_query_splay_window`, default 30m, 0 to disable), instead of sending them to every host at once. This reduces database writer load spikes after Fleet downtime of 30 minutes or more.
* Reduced database writer load during heavy check-in periods: host-reported label results, software inventory, and software installed paths are no longer retried in place on lock contention (deadlocks, lock wait timeouts); the failed update is logged and picked up again on the host's next check-in or refresh.
* Skipped the per-check-in recompute of the host's failing policies count when the reported policy results leave the count unchanged, removing a database writer statement from every steady-state host check-in.
