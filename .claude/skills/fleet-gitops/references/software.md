# Software and patching

All software lives under `software:` in a fleet file (never `default.yml`) and needs Fleet Premium. Decide the source in this order, and say which you chose:

1. **Fleet-maintained app** (`fleet_maintained_apps`): Fleet hosts the installer, keeps it current, and ships verified install, uninstall, and detection queries. Check the catalog first for macOS and Windows apps: https://github.com/fleetdm/fleet/blob/main/ee/maintained-apps/outputs/apps.json lists every `slug` as `<app>/darwin` or `<app>/windows`. The validator checks slugs against it; `fleetctl gitops` fails on a slug that doesn't exist.
2. **App Store / Google Play app** (`app_store_apps`): iOS, iPadOS, macOS (VPP) and Android apps, by store id.
3. **Custom package** (`packages`): a `.pkg`, `.dmg`, `.msi`, `.exe`, `.deb`, `.rpm`, `.tar.gz`, or `.ipa` the user hosts or already uploaded, described by a small YAML file.
4. **Script-only package**: a `.sh`, `.ps1`, or `.py` referenced directly; its contents become the install script.

## Fleet-maintained apps

```yaml
software:
  fleet_maintained_apps:
    - slug: slack/darwin # Slack for macOS
      self_service: true
      setup_experience: true
      categories:
        - Communication
      labels_include_any:
        - Macs with Slack installed
```

- `slug` is `<app>/<darwin|windows>`; some Windows apps have a separate `<app>-arm64/windows`. Most repos scope Windows apps with an architecture label (for example "x86-based Windows hosts") because an x64 installer fails on ARM.
- `self_service: true` shows it in Fleet Desktop; `setup_experience: true` installs it during enrollment. `display_name` overrides the catalog name.
- `version: "4.47.65"` pins a version; `"^26"` tracks the latest within a major. Omit it to follow Fleet's latest. Always a quoted string.
- `categories`: omit to keep the catalog defaults, `[]` to remove them, or list your own (which replace the defaults). Category names must match the repo's existing spellings; emoji are ignored for uniqueness.
- `install_script`, `uninstall_script`, `post_install_script`, `pre_install_query`, `icon` are `path:` overrides and rarely needed. A patch policy with `patch_when_closed` or `notify_before_patching` owns `pre_install_query`, so don't set both.
- One app per slug per fleet; the same software defined twice (or once as a package and once as a Fleet-maintained app) keeps only one.

## Keeping apps current: patch policies

A patch policy fails on hosts running anything older than the catalog version (or the pinned `version`) and, with `install_software: true`, installs the update. The query is generated by Fleet; don't write one.

```yaml
- name: Slack up to date (macOS)
  description: The host may have an outdated version of Slack, potentially risking security vulnerabilities or compatibility issues.
  resolution: Download the latest version from Self-service or check for updates using Slack's built-in update functionality.
  type: patch
  fleet_maintained_app_slug: slack/darwin
  install_software: true
  patch_when_closed: true
  labels_include_any:
    - Macs with Slack installed
```

- The app must be in the same fleet's `fleet_maintained_apps`.
- `patch_when_closed: true` waits until the app isn't running, so users don't lose work. `notify_before_patching: true` (macOS, needs the Fleet Desktop app) warns the user an hour ahead instead. Without either, the update is forced immediately. Either option also sets `continuous_automations_enabled`.
- Scope it with the "installed" label the repo uses for that app so hosts without the app don't fail it; add that label if it's missing (`SELECT 1 FROM apps WHERE bundle_identifier = '…'` on macOS, `SELECT 1 FROM programs WHERE name …` on Windows). The `unique_identifier` for each app is in `apps.json`.
- Setting `patch_when_closed` or `notify_before_patching` without `install_software: true` produces a policy that reports but never patches; that mistake has shipped before.

## Custom packages

The package file (one per app, in the platform's `software/` folder):

```yaml
url: https://downloads.example.com/app-1.2.3.pkg
# or, for a package already uploaded to Fleet:
# hash_sha256: fd22528a87f3cfdb81aca981953aa5c8d7084581b9209bb69abf69c09a0afaaf
display_name: Example App
install_script:
  path: ../scripts/example-install.sh      # relative to this package file
uninstall_script:
  path: ../scripts/example-uninstall.sh
post_install_script:
  path: ../scripts/example-configure.sh
pre_install_query:
  path: ../queries/example-precheck.yml
icon:
  path: ../../all/icons/example.png        # square PNG, 120 to 1024 px
```

The fleet file entry carries the targeting: `path`, `self_service`, `setup_experience` (and `setup_experience_platform` for `.sh`, `.py`, `.ipa`), `categories`, `labels_*`, `display_name`.

- `url` must be a direct, stable download; Fleet downloads it on each GitOps run (ETag-conditional unless `always_download: true`) and uploads it to its own storage. Verify the URL resolves to the expected file type and architecture before committing; a URL you only inferred isn't verified. Secrets or per-environment hosts go in a `$VARIABLE`, as the repo already does for other URLs.
- `hash_sha256` (64 lowercase hex chars) refers to a package already in Fleet; with `url` it skips the download when the hash matches. Get it from the software's page in the Fleet UI.
- `.exe` and `.tar.gz` require both `install_script` and `uninstall_script`. Other types get Fleet's default scripts; `.msi` installs with `msiexec /quiet /norestart`.
- A package file may also be a list of packages for staged rollouts or per-architecture installers, each with its own labels.
- Linux: scope `.deb` to Debian-based hosts and `.rpm` to RPM-based ones with the repo's distro and architecture labels; a `.deb` offered to a Fedora host just fails.
- Script-only packages (`.sh`, `.ps1`, `.py`) don't support install, uninstall, or pre-install overrides or `install_software` automations; set `display_name` and an `icon` inline.

## App Store and Google Play apps

```yaml
app_store_apps:
  - app_store_id: "546505307" # Zoom
    platform: ios
    self_service: true
    auto_update_enabled: true
    auto_update_window_start: "21:00"
    auto_update_window_end: "05:00"
    categories:
      - Communication
  - app_store_id: "us.zoom.videomeetings"
    platform: android
    self_service: true
    configuration:
      path: ../software/zoom-config.json
```

- `app_store_id` is the numeric id from the App Store URL (quoted, no `id` prefix) or the Play Store package name. `platform` is `darwin`, `ios`, `ipados`, or `android`; without it, an Apple id adds every platform the app supports.
- Apple apps need the fleet listed under `org_settings.mdm.volume_purchasing_program` for that location; otherwise the dry run fails with a VPP error.
- `auto_update_*` is iOS and iPadOS only; both window times are required when enabled and must be quoted `HH:MM`.
- `configuration.path` is the app's managed configuration (XML for Apple, JSON for Android); keys come from the app vendor's documentation.

## Remediating a CVE

1. Identify the affected software title and the fixed version. The user may give it to you; otherwise Fleet's vulnerability pages (Software > Vulnerabilities, or `GET /api/v1/fleet/vulnerabilities/<CVE>`) list affected titles and versions.
2. If the title is a Fleet-maintained app, make sure it's in the affected fleets' `fleet_maintained_apps` and has a patch policy (above). Pin `version` only if the user wants a specific build; the catalog's latest usually is the fix.
3. Otherwise add or update a custom package to the fixed version and pair it with a policy that fails below that version (`version_compare`) and installs it (`install_software.package_path`).
4. For OS-level CVEs use `macos_updates` / `windows_updates` / `ios_updates` deadlines in `controls`, not software.
5. Report which fleets and labels get the fix, whether the install waits for the app to close or is forced, and anything you couldn't confirm (for example the exact fixed version).

## Checks before you report

- Every slug exists in the catalog; every `app_store_id` and `version` is a quoted string; `categories` and label names match existing spellings.
- Any policy automation points at software defined in the same fleet file.
- A custom package URL was fetched (HEAD or range request) and the file type matches the extension; hashes are 64 lowercase hex characters.
- Icons are square PNGs within 120 to 1024 px.
- The validator (`scripts/validate.py`) passes, and the dry run was run or you said why it wasn't.
