How this is measured

Clock starts the day Apple or Microsoft released the version, for macOS and Windows. For apps and Linux, it starts the first day Fleet sees the version on any computer. Clock stops the day each computer reports it. Days are wall-clock days.

Who's counted: only computers seen completing an update. One still on the old version isn't in the timing numbers yet, so the real picture is slower than shown, never faster. Fresh installs and downgrades aren't updates. Virtual machines are left out.

History: Fleet keeps current versions only, so this page records a daily snapshot and times new versions from . Versions already installed the first day an app or OS appears in the history aren't timed.

Newest version: for macOS, Apple's newest release from SOFA, the Mac admins' public feed of Apple's updates. For Windows, the newest security build Microsoft lists in its Security Update Guide, across every release of that Windows version. For an app with a patch policy, the version the policy asks for, the latest in Fleet's maintained-apps catalog. Anything else is measured against the highest version at least two computers run. Each run checks the sources again, so the share on the newest version drops the day a new release ships and climbs as computers update.

Patched: an OS on the latest update for the release it runs, such as macOS 26.7.2 or Windows 11 25H2's newest build, even when a newer release exists. Missing updates: an update for the release it runs is out but not installed. No longer updated: the release gets no more security updates, so only an upgrade fixes it. On macOS, that's a major version Apple hasn't updated since the newest one shipped. On Windows, it's a release missing from Microsoft's latest monthly security update. macOS betas (builds ending in a letter) and Windows Insider builds count as current but aren't timed.

Scope: on macOS, the OS plus third-party apps in /Applications. On Windows, the OS build across Windows 11's releases (for example 25H2 and 26H2) plus third-party programs. On Linux, the point release within each distribution release (for example Ubuntu 24.04.5 within 24.04) plus apps whose vendors ship their own Linux packages, such as Chrome, VS Code, Slack, and Zoom. Apps the distribution builds, such as LibreOffice and Ubuntu's Firefox, update with the OS and aren't timed on their own. Kernels aren't timed either, since a new kernel only runs after a restart. Apple's and Microsoft's own apps and components update on their own schedule and are left out, as are helpers and installers. Computers that haven't checked in for days are left out of the version counts.

Target: days from release to install. Medians are used because patch times have a long tail.

Patch policy: Rollouts in progress can show only apps with a patch policy in Fleet, counted on the computers each policy applies to. A policy is matched to an app by the bundle ID (macOS) or program name (Windows) in its query.
