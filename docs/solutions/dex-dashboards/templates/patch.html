How this is measured

Clock starts the first day Fleet sees a new version on any computer. Clock stops the day each computer reports it. Days are wall-clock days, read once a day.

Who's counted: only computers seen completing an update. One still on the old version isn't in the timing numbers yet, so the real picture is slower than shown, never faster. Fresh installs and downgrades aren't updates. Virtual machines are left out.

History: Fleet keeps current versions only, so this page records a daily snapshot and times new versions from . Versions already installed the first day an app or OS appears in the history aren't timed.

Newest version: the highest version that at least two computers run, so a lone test build doesn't count. macOS betas (builds ending in a letter) and Windows Insider builds are left out, and computers running one count as current.

Scope: on macOS, the OS plus third-party apps in /Applications. On Windows, the OS build within each release (for example 25H2) plus third-party programs. On Linux, the point release within each distribution release (for example Ubuntu 24.04.5 within 24.04) plus apps whose vendors ship their own Linux packages, such as Chrome, VS Code, Slack, and Zoom. Apps the distribution builds, such as LibreOffice and Ubuntu's Firefox, update with the OS and aren't timed on their own. Kernels aren't timed either, since a new kernel only runs after a restart. Apple's and Microsoft's own apps and components update on their own schedule and are left out, as are helpers and installers. Computers that haven't checked in for days are left out of the version counts.

Target: days from release to install. Medians are used because patch times have a long tail.
